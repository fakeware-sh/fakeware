Publish a plugin as its own package that depends on `@fakeware/core` as a **peer dependency**, and add the `fakeware-plugin` keyword to `package.json` so it's discoverable:

```json [package.json]
{
  "name": "@you/fakeware-plugin-thing",
  "keywords": ["fakeware-plugin"],
  "peerDependencies": {
    "@fakeware/core": ">=0.1.0 <0.2.0"
  },
  "devDependencies": {
    "@fakeware/core": "^0.1.0"
  }
}
```

::note
Using a peer dependency (rather than a regular dependency) ensures the plugin runs against the **same** `@fakeware/core` the host project uses, so context types and tokens line up. Keep it as a devDependency too, so your own tests and typecheck have something to resolve.
::

Bound the range at the next minor. Core is pre-1.0, so minors can carry breaking changes, and an open-ended `>=` range will eventually resolve your plugin against a core it was never tested on. `fakeware init --template plugin` writes a correctly bounded range for the core version you scaffolded against.

Point users at your plugin's factory in their config:

```ts [fakeware.config.ts]
import { thing } from '@you/fakeware-plugin-thing'

export default defineConfig({
  shopware: { /* … */ },
  plugins: [thing()],
})
```
